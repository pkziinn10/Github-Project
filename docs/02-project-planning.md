# 2. Roadmap e Planejamento Inicial

Gerenciar um projeto sem planejamento é como dirigir sem destino. O Roadmap é a bússola que orienta o desenvolvimento e diz onde o produto deve estar daqui a algumas semanas ou meses.

## O problema
Muitas equipes usam ferramentas de gestão complexas separadas do código, criando uma quebra de contexto. Os desenvolvedores esquecem de atualizar as tarefas e o gerente de projeto perde a visão real do andamento.

## A solução: Planejamento próximo ao código
Trazer o planejamento para dentro do GitHub diminui o atrito. Usamos o **Roadmap** para definir a visão e as **Milestones (Marcos)** para fatiar essa visão.

### 2.1 Definindo o Roadmap
Um Roadmap deve ser simples. Em vez de prever o ano inteiro em detalhes (o que nunca funciona), preveja os próximos 2 a 3 marcos principais do seu projeto.
* Exemplo: *Fase 1 (MVP) -> Fase 2 (Cadastro de Usuários) -> Fase 3 (Pagamentos).*

### 2.2 Usando Milestones
As Milestones do GitHub são perfeitas para representar as fases do Roadmap.

**Como funciona:**
* Uma Milestone representa uma grande entrega (ex: `v1.0.0 - MVP`).
* Ela possui uma **Data Limite (Due Date)** opcional.
* Todas as tarefas (Issues) necessárias para concluir o MVP são vinculadas a esta Milestone.
* O GitHub calcula automaticamente a barra de progresso com base nas Issues fechadas.

### 2.3 Mantendo o foco
Ao planejar o seu projeto, não crie centenas de Issues de uma vez. Crie apenas as Issues necessárias para a Milestone atual. Isso mantém o *Backlog* limpo e gerenciável.

### Benefícios x Custos
* **Benefícios:** Visibilidade clara de progresso. Ajuda a equipe a dizer "não" para tarefas que não pertencem à Milestone atual.
* **Custos:** Exige disciplina para planejar antes de executar e revisar periodicamente.
* **Quando dispensar:** Projetos de estudo focados apenas em um fim de semana (hackathons) não costumam necessitar de Milestones complexas.
