# 4. Milestones e Ciclos de Entrega

No desenvolvimento ágil, tentar planejar o fim do projeto é quase impossível. No entanto, é fundamental planejar a próxima entrega de valor. As Milestones são a forma nativa do GitHub para organizar essas fases.

## O problema
As equipes acumulam milhares de tarefas no repositório sem saber quando elas devem ser entregues ou o que compõe uma versão viável do software. Isso gera desmotivação e falta de alinhamento com stakeholders.

## A solução: Fatiar para Entregar
A Milestone funciona como uma "caixa" com prazo de validade. Você coloca dentro dessa caixa apenas o que é essencial para concluir aquele marco.

### 4.1 O que define uma Milestone?
Um bom marco deve ter:
1. **Um objetivo claro:** Exemplo: "Permitir que o usuário se cadastre e faça login".
2. **Prazo estipulado (Due Date):** Uma data alvo que force a equipe a não aumentar o escopo.
3. **Escopo fechado:** Uma vez iniciada, não adicionamos novas Issues à Milestone, a menos que seja um bloqueador crítico.

### 4.2 Acompanhamento de Progresso
Quando vinculamos Issues a uma Milestone, o GitHub gera automaticamente uma barra de progresso. Isso elimina a necessidade de reuniões longas de status. Basta olhar a Milestone para saber o percentual de conclusão.

### Benefícios x Custos
* **Benefícios:** Alinhamento claro do que importa no momento. Facilita muito a priorização do Backlog.
* **Custos:** O gestor ou equipe deve revisar o escopo constantemente para não incluir tarefas irrelevantes na Milestone atual.
* **Quando dispensar:** Projetos de manutenção contínua, onde apenas bugs pontuais são corrigidos (sem a busca por uma nova "versão" de impacto).
