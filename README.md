# GitHub Project Playbook

Um guia público, educacional e prático sobre como organizar e gerenciar projetos de software usando exclusivamente os recursos nativos do GitHub. 

## Qual problema este playbook resolve?
Muitos desenvolvedores, equipes e estudantes utilizam o GitHub apenas como uma plataforma de armazenamento de código, sem aproveitar seu potencial para o gerenciamento de demandas. O resultado, frequentemente, é a falta de visibilidade, dificuldade de colaboração, ou dependência de ferramentas externas complexas e burocráticas.

Este projeto visa demonstrar que é possível e altamente eficaz planejar, executar e entregar software de ponta a ponta sem sair do GitHub.

## Público-alvo
* Estudantes universitários em projetos acadêmicos;
* Desenvolvedores autônomos organizando projetos pessoais;
* Pequenas equipes e startups desenvolvendo MVPs;
* Grupos de pesquisa e extensão;
* Qualquer pessoa interessada em simplificar o gerenciamento de software.

## Objetivos
1. **Educar através da prática:** Ensinar o fluxo de gestão de forma concreta e aplicável;
2. **Reduzir ferramentas:** Mostrar o poder de manter código e planejamento juntos;
3. **Oferecer flexibilidade:** Prover modelos de processos adaptáveis.

## Visão Geral do Fluxo
O playbook conecta de forma lógica os seguintes elementos do GitHub:
`Projeto → Roadmap → Milestones → Issues → GitHub Project (Kanban) → Branches → Pull Requests → Releases`.

## Adoção: Individual vs. Equipe
Existem duas formas principais de seguir este material:
* **Fluxo mínimo (Projetos individuais):** Adota apenas os elementos vitais (ex: Issues, PRs e Branches simples) para garantir organização com o mínimo de sobrecarga.
* **Fluxo completo (Pequenas equipes):** Adiciona revisões (Code Review), limites de WIP (Work in Progress), convenção de commits e retrospectivas, garantindo estabilidade e colaboração saudável.

## Princípios do Projeto
* **Sem burocracia:** O processo deve facilitar o trabalho, não atrapalhar;
* **Pragmatismo:** Tudo deve ter uma razão clara para existir;
* **Evolução contínua:** Comece pequeno e adote práticas conforme a necessidade aumenta.

## Conteúdo Planejado
1. Preparação do repositório
2. Roadmap e Planejamento
3. Configuração do Kanban (GitHub Projects)
4. Milestones
5. Decomposição e gestão de Issues
6. Branches e Conventional Commits
7. Pull Requests e Revisão de código
8. Releases e versionamento
9. Fluxo de trabalho completo
