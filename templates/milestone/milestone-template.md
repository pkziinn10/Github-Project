# Template: Milestone

Use este modelo como referencia para planejar e documentar suas Milestones no GitHub. Ele nao e um arquivo que o GitHub le automaticamente, mas sim um guia para manter a consistencia do seu planejamento.

---

## Estrutura Recomendada

### Titulo
Use o formato de versionamento semantico quando possivel.
Exemplo: `v1.0.0 - MVP do Sistema`

### Descricao
A descricao da Milestone deve responder a tres perguntas:
1. **O que sera entregue?** (Objetivo principal do marco.)
2. **Para quem?** (Qual usuario ou stakeholder se beneficia.)
3. **Qual o criterio de conclusao?** (O que define que a Milestone esta pronta.)

Exemplo:
> Entregar a versao minima viavel do sistema de cadastro, permitindo que
> usuarios criem conta e facam login. A Milestone sera considerada concluida
> quando todas as Issues vinculadas estiverem fechadas e o deploy em ambiente
> de homologacao estiver funcional.

### Prazo (Due Date)
Defina uma data limite realista. O prazo serve como ancora para a priorizacao das tarefas, nao como uma promessa rigida.

### Regras de Ouro
- Nao adicione novas Issues a uma Milestone ja iniciada, a menos que seja um bloqueador critico.
- Se o escopo crescer, crie uma nova Milestone para a proxima iteracao.
- Mantenha o numero de Issues entre 5 e 15 por Milestone. Menos que isso pode ser pouco ambicioso; mais que isso pode ser ingerenciavel.
